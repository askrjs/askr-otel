## Executed hardening matrix

Existing assertions were inspected: nested spans/contexts, response identity,
raw exception suppression, redaction, Unicode caps, unreadable getters/Proxy
traps and synchronous sink failures were already covered.

| Probe                                   | Outcome and evidence                                                                                                                                                                                                                                  |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Rejected async sinks                    | Previously produced two unhandled rejections; returned promises are now observed without awaiting the sink. Original application result/error and exact-once span end remain intact.                                                                  |
| Undefined thrown/rejected values        | Previously marked success; explicit rejection state now records error while preserving `undefined`.                                                                                                                                                   |
| Hostile exception inspection            | A throwing prototype trap previously replaced the original error and skipped span completion. Inspection is now isolated and the original value survives; the span ends once.                                                                         |
| Provider failures before/after callback | Previously replaced results/errors or skipped work. Remember the original work outcome and never execute it twice; tests verify before/after synchronous failure, provider error replacement and post-callback async rejection.                       |
| Nested/malformed/transformed fields     | Previously forwarded nonfinite/mismatched scalar fields. The field boundary now requires finite numeric status/duration and string identities both before and after sanitization. Nested/circular secrets are dropped without invoking the sanitizer. |
| Limits and repeat behavior              | Invalid zero/negative/fractional/nonfinite caps reject before work; Unicode bounds remain intact. All four severities are forwarded in 100 repeated calls; filtering belongs to the sink.                                                             |
| Installed boundary                      | Normal tarball installation with minimum OpenTelemetry API 1.9.1 checks runtime/result/error identity, async sink rejection, metadata/private paths, generic result types and every removed type alias.                                               |

The final expanded tests first ran against unchanged source: eight failed
assertions and three unhandled rejections. The final suite passes 34 tests.

## Async dropped-field diagnostics follow-up (2026-10-12)

The original follow-up source `6a249c6e9124b95d221989b1d73172ef898f9ebf`
isolated synchronous `onDroppedField` throws but ignored its returned promise.
On Node 24.21.0, a rejecting async diagnostic terminated a direct source-import
consumer after its instrumented work had successfully returned. The focused
regressions also exited unsuccessfully on that source because a pending
diagnostic's late rejection was unhandled.

The diagnostic now observes returned promises with the same rejection-isolation
pattern as the logger. It does not await diagnostics. Two new tests retain
synchronous result identity, original synchronous/asynchronous failure identity,
exact-once work/span completion, allowlisted log output, and immediate return
while the diagnostic is pending. The installed consumer also exercises rejected
diagnostics through log, synchronous request and rejected loader work; its
declaration check accepts the async callback.

Executed with Node 24.21.0 and npm 11.19.0:

- `npm test -- --reporter=verbose -t 'async field diagnostic'`: original source
  exits 1 with an unhandled rejection; fixed source passes both focused cases.
- The direct Node source-import reproduction changes from exit 1 to exit 0.
- `npm run check`: all 36 tests, lint/types, builds, normally installed packed
  runtime/types at the minimum OpenTelemetry peer, publint and archive checks
  pass.
- `npm run fmt -- --check` and the whitespace check pass.

This follow-up changes no export names or manifest versions. Promotion PR #41
retains the fix and passes exact-head package checks on Linux, macOS and Windows,
including the packed consumer, plus CodeQL.
`npm run check` on Node 24 LTS passes lint/types, tests, build, real packed
runtime/type consumer, publint and artifact checks. CI also runs the packed
consumer and publint on all three operating systems. Branch evidence is the
explicit assertions above; no coverage percentage is claimed.

The instrumentation contract documents application ownership of embedded-secret
redaction, field naming/cardinality, severity filtering, and exporter
flush/shutdown. These are explicit policies, not automatic application inference.
